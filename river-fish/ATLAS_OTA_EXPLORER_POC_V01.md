# 日本の河川大図鑑｜太田川水系の探索試作 v0.1

状態：**GitHub研究用・未公開**。WordPress／Xserver／既存生物DBには接触しない。

## 今回できる体験

「広島県（2021年広島県資料にある太田川の入口）」→「太田川水系（870709）」→「国交省河川コードに所属する川の名前の一覧」→「個別河川のコード表示」。

一覧は実在する10桁コードを重複保持し、36件ずつ表示。川名で絞り込み、詳細・一覧へ戻れる。iPhone向け幅でカードを二列にする。地理上の親子・合流先は表示しない。

水系画面の「魚類調査」には、国交省の中国地方・太田川という **地域＋水系名** で収録された年度付き魚名レコードを別枠で表示。**全国水系コード870709との公式な同一IDによる照合は未承認**、また各支流の生物ではない。

## データの取り方

独立の新CSVを作らず、検証済み `build_river_beta_v15.create_payload()` を再利用する。ソースは `national-codes-staged/river_codes_national_v07.csv` と `watershed_codes_national_v07.csv`、広島県資料掲載行、`nationwide-staged/*/watershed_year_fish.csv`。

1. 国交省公式水系コード `870709` が `太田川` と一意に一致することを照合。
2. 10桁コードの先頭6桁が `870709` のレコードだけ抽出。
3. 県資料に「広島県／太田川／三篠川」等の掲載行が存在することを**入口の根拠**として確認。ただし、国のコード一覧の各川の所在県は未確認のまま。
4. 魚類調査は `region=chugoku, watershed=太田川` の**原掲載名**のみを抽出し、コード付き河川へ結合しない。
5. 自動テストが既存の収録数、所在地の非承認、河川コードの同一性、出典境界、オフライン出力をチェック。

## オフラインでの作り方

```bash
python -m unittest discover -s river-fish -p 'test_river_atlas_poc_v01.py' -v
python river-fish/build_river_atlas_poc_v01.py --out /tmp/ota-atlas --zip /tmp/ota-atlas.zip
```

ZIPを展開し、同じフォルダの `index.html` と `data.js` をそのまま開く。Xserver APIやログインは不要。GitHub Actionsの `Ota watershed atlas proof-of-concept (offline only)` もZIP Artifactを生成する。ZIPは再現可能なQA成果物であり、サイト公開ではない。

## 本番へ持ち込む前の条件

- 県→水系：公的資料掲載という弱い入口と、各河川の所在地確認を分離。別県にまたがる水系は多対多の対応にする。
- 既存 `tsurikue-river-search` プラグインの導入準備版 v1.6 や公開済みか未確認の検索システムを置換しない。
- 生物：実稼働の `/biota/api/search.php` の**JSON契約とサーバー側テーブル構造は未検証**。この試作はGitHubにある魚類18,814行の研究スナップショットだけで、稼働中の408,036件を再インポートしない。
- 未解決の19河川コード行は名前一致で補修せず、本番APIでは未照合として管理。
- 本番はJSONをブラウザ一括配布せず、Xserver PHP/MySQLの読み取り専用API、明示的なページング、コード／水系コード索引を使う。
- 国交省コード表・広島県資料・河川水辺の国勢調査の利用条件と加工表示を公開前に再審査する。旧W05河川線データは使わない。
- セキュリティ：APIの入力制限・ページング・prepared statement・CORS・レート制限・HTML出力エスケープ。希少種の詳細地点は扱わない。
- 実機：iPhone Safariで横幅、タップ、スクロール、絞り込み、戻る、画面回転、VoiceOverなどを確認。
